# HL7 v2 就诊消息本地接入服务

一个零外部依赖（除 Spring Boot Web 外）的本地 HL7 v2 ADT 接入服务：接收发送方推送的
原始报文，解析为可查询的患者/就诊数据，按业务时间做幂等与状态合并，并回 HL7 ACK 确认。
所有数据保存在进程内存中，不接数据库、不调外部系统，`mvn spring-boot:run` 即可复现全部结论。

## 一、接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/hl7/messages` | 接收原始 HL7 v2 报文（`text/plain` 或 `application/hl7-v2`），始终回 `application/hl7-v2` ACK |
| GET | `/api/patients` | 患者列表（脱敏视图） |
| GET | `/api/visits` | 就诊列表（脱敏视图） |
| GET | `/api/messages` | 已处理消息的幂等记录（控制号、处置结果、原文 SHA-256） |
| GET | `/api/conflicts` | 合并冲突判定记录（乱序拒收 / 同时刻裁决 / 控制号复用） |

解析失败也返回 HTTP 200 + `MSA|AE|...` 失败确认，绝不抛 5xx。

## 二、支持的消息范围与版本

- 版本（MSH-12.1）：`2.3`、`2.3.1`、`2.4`、`2.5`、`2.5.1`；其余版本返回
  `HL7-1007 UNSUPPORTED_VERSION`（错误位置 `MSH-12.1`）。
- 消息类型：`ADT`，触发事件 `A01`（入院）、`A02`（转科）、`A03`（出院）、
  `A04`（登记/门诊挂号）、`A08`（信息更新）；其余返回 `HL7-1010`。
- 分隔符全部从 MSH 动态推导（MSH-1 字段分隔符 + MSH-2 的 `^ ~ \ &`），不写死。
- 完整还原 段 / 字段 / 重复 / 组件 / 子组件 五层结构，访问位置如 `PID-3[2].5.1`。
- 转义：`\F\ \S\ \T\ \R\ \E\` 全版本支持，2.4+ 额外接受十六进制 `X..` 与
  `\H\ \N\ \.br\` 等格式转义；非法/未闭合转义返回 `HL7-1005 INVALID_ESCAPE`，
  并定位到具体字段（如 `PID-5[1].1`）。
- 行结束符接受 `\r`、`\n`、`\r\n` 混用；非 UTF-8 字节返回 `HL7-1004 ILLEGAL_ENCODING`。
- 日期时间（DTM）兼容 2.3 的 `yyyyMMddHHmmss` 与 2.5 带时区形式 `20240304090000+0800`，
  内部统一换算为 UTC 后比较。

### 2.3 与 2.5 的常用差异兼容

| 差异点 | 2.3 | 2.5 | 服务处理 |
| --- | --- | --- | --- |
| MSH-9 消息类型 | `ADT^A01` | `ADT^A01^ADT_A01`（含结构码） | 按版本取 MSH-9.1/9.2，ACK 的 MSH-9 按对应版本回 |
| PID-3 标识符类型 | CX-5 为 IS 码 | CX-5 为 CWE（码在 5.1，体系在 5.3） | 统一取 CX-5.1 |
| PID-13 电话 | XTN-1 即号码 | 号码在 XTN-7 | 先取 XTN-7，空则回退 XTN-1 |
| 业务时间 | 常用 PV1-44 入院时间 | 转科/出院用 PV1-45 | EVN-2 → PV1-45(A02/A03) → PV1-44 → MSH-7 |
| ACK/ERR | ERR 紧凑 ELD 形式 | ERR-1 ERL + ERR-2 HL70357 + ERR-4 严重级别 | 按入站版本选择 ERR 形态 |

## 三、幂等与合并规则

- **幂等键**：`发送方设施(MSH-4) | 发送方应用(MSH-3) | 控制号(MSH-10)`。
  - 同键且原文 SHA-256 相同：`MSA|AA` + 处置结果 `DUPLICATE`，不产生任何重复数据或副作用。
  - 同键但原文不同（控制号被复用）：返回 `AE`，并写入 `IDEMPOTENCY_MISMATCH` 冲突记录。
- **就诊键**：`发送方设施 + 患者标识(PID-3 首个非空重复) + 就诊号(PV1-19)`，
  PV1-19 缺失时按“发送方+患者”确定性回退，保证同患者多次事件落在同一就诊。
- **业务时间合并**：同一就诊只接受业务时间更新的事件；乱序到达的旧事件被拒绝
  （处置结果 `STALE`），并写入 `STALE_REJECTED` 冲突（含双方控制号与时间）。
- **同一业务时刻的并发竞争**按确定规则裁决，结果可复现：
  1. 状态机优先级：`DISCHARGED > ADMITTED > TRANSFERRED > UPDATED > REGISTERED`；
  2. 仍相同则控制号字典序较小者胜；
  裁决写入 `SAME_TIME_RESOLVED` 冲突记录。
- 全部判定在单把存储锁内串行完成，8 线程并发上报测试中结论稳定（就诊数恒为 1）。
- ACK 处置结果取值：`ACCEPTED` / `DUPLICATE` / `STALE` / `CONFLICT_RESOLVED` /
  失败时 `MSA=AE`。AA 表示“服务已受理并给出确定结论”，乱序拒收属于业务语义确认而非错误。

## 四、错误码与确认

每条失败确认都带稳定错误码、HL7 Table 0357 条件码与出错位置：

| 错误码 | 条件码 | 含义 |
| --- | --- | --- |
| HL7-1001 | 100 | 空报文 |
| HL7-1002 | 102 | 首段不是 MSH |
| HL7-1003 | 102 | MSH 过短，无法声明分隔符 |
| HL7-1004 | 207 | 非 UTF-8 / 非法字符 |
| HL7-1005 | 207 | 非法转义序列（位置定位到字段/重复/组件） |
| HL7-1006 | 102 | 空段 |
| HL7-1007 | 203 | 版本不受支持 |
| HL7-1008 | 101 | 必填字段缺失（如 PID-3、PID-5、MSH-10） |
| HL7-1009 | 207 | 非法日期时间 |
| HL7-1010 | 200 | 不支持的消息类型/触发事件 |

## 五、脱敏策略

- 内存模型虽保存原始字段用于合并，但**对外响应与日志只出现脱敏值**：
  - 姓名：保留首末字符（`王**五`）；
  - 证件号/就诊号：保留后 4 位 + SHA-256 前 10 位短哈希（`****0001#57eada084f`）；
  - 电话：仅保留后 2 位 + 短哈希；
  - 出生日期：仅保留年份（`1986****`）；
  - 患者/就诊内部引用为不可逆哈希键（`P#…`、`V#…`），同一数据跨接口可关联。
- 每条消息生成 `correlationId`（原文 SHA-256 短哈希），ACK MSH-10 与日志均带该标识，
  可在不含任何 PHI 的前提下串联排查；日志从不打印报文原文。

## 六、本地验证方法

前置：JDK 21+、Maven 3.9+（仓库依赖已在本地 Maven 缓存时可离线 `mvn -o`）。

```bash
# 1. 跑测试（日志会逐行打印“业务 | 用例 | 结果”覆盖矩阵）
mvn test

# 2. 启动服务（默认 8080；端口被占用时可换 --server.port=8088）
mvn spring-boot:run

# 3. 推送一条 2.3 A01（注意必须是 CR 行结束、--data-binary 保留原始字节）
printf 'MSH|^~\\&|HIS|HOSP-A|INGEST|LOCAL|20240301080000||ADT^A01|MSG-0001|P|2.3\r'\
'EVN|A01|20240301080000\r'\
'PID|1||PAT-0001^^^MR||王^小五||19860512|M|||||^HOME^PH^^^^13912345678\r'\
'PV1|1|I|内科^301^02^总院|\r' \
| curl -s -X POST http://localhost:8080/hl7/messages \
  -H 'Content-Type: application/hl7-v2' --data-binary @-

# 4. 查询脱敏数据与冲突判定
curl -s http://localhost:8080/api/patients
curl -s http://localhost:8080/api/visits
curl -s http://localhost:8080/api/conflicts
```

## 七、测试覆盖

`mvn test` 共 23 个用例，按业务分组（命名格式 `业务: … | 用例: … -> 结果: …`，
由 `BusinessCoverageLoggingListener` 逐行输出到测试日志）：

- 解析：五层结构/重复、2.3→2.5 标识符差异、F/S/T/R/E 转义、非法转义定位、
  空报文、非 MSH 开头、非 UTF-8、版本缺失/超范围、混合行结束符；
- 幂等合并：完全重复、控制号复用、乱序 STALE、A01→A02→A03 生命周期、
  同业务时刻优先级裁决、8 线程并发确定性；
- 确认与脱敏：2.3 AA、损坏报文 200+AE、2.5 ERR（ERL 位置 + HL70357）、
  查询接口不出现姓名/证件号/电话原文。
